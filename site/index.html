      From scattered talk to facts with dates on them

      Three steps, one pipeline. Every source goes through the same path, so an answer about a Slack thread and an answer about a pull request rest on the same graph.

      1. 1

        Connect

        Slack, GitHub, Jira and Notion stream in. Every message, PR, ticket and page goes through the same pipeline.

      2. 2

        Remember

        Each change becomes a decision with a start and end date, who made it and the quote that proves it. Nothing is deleted: old facts get an end date.

      3. 3

        Act

        Ask in Slack, the web app or any AI agent over MCP. When new talk contradicts a decision, Lore raises an alert with its blast radius and a drafted fix. One click on Approve posts it back to Jira and GitHub.

      Why it has to be a graph

      The answers above come from structure no pile of text chunks holds: time windows, links between ids, and who works with whom. FalkorDB runs all three natively.

      // states_at.cypher: the decisions in force at one moment
MATCH (:Product {id: $product_id})<-[:IN_PRODUCT]-(i:Issue)<-[:AFFECTS]-(d:Decision)
WHERE d.kind = 'issue_status' AND d.valid_from_ms <= $as_of_ms
  AND (d.valid_to_ms IS NULL OR d.valid_to_ms > $as_of_ms)
RETURN i.id AS subject_id, d.value AS value, d.id AS decision_id
LIMIT $limit// rank_companies.cypher: companies by the issues their customers reported
MATCH (:Product {id: $product_id})<-[:IN_PRODUCT]-(i:Issue)-[:REPORTED_BY]->(c:Customer)
OPTIONAL MATCH (c)-[:WORKS_AT]->(co:Company)
OPTIONAL MATCH (i)-[:REPORTED_IN]->(m:Artifact)
// … group by company, keep each issue's status and report as evidence
RETURN key AS id, name, issues
LIMIT $limit// person_pagerank.cypher: FalkorDB's native PageRank over who works with whom
CALL algo.pageRank('Person', 'COLLAB') YIELD node, score
RETURN node.id AS id, score
ORDER BY score DESC
LIMIT $limit
// also native: algo.betweenness, algo.labelPropagation, shortestPath
