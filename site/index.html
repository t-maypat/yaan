      Connect your tools. Yaan remembers what changed. You act on it.

      Three steps, one pipeline. Every source goes through the same path, so an answer about a Slack thread and an answer about a pull request rest on the same graph.

      1. 1

        Connect

        Slack, GitHub, Jira and Notion stream in. Every message, PR, ticket and page goes through the same pipeline.

      2. 2

        Remember

        Each change becomes a decision with a start and end date, who made it and the quote that proves it. Nothing is deleted: old facts get an end date.

      3. 3

        Act

        Ask from Claude Code, Codex, Cursor or Slack. When new talk contradicts a decision, Yaan raises an alert with its blast radius and a drafted fix. One click on Approve posts it back to Jira and GitHub.

      Open source. Self‑hosted. Yours.

      Yaan runs on your own servers under the Apache-2.0 license. Your company’s knowledge stays inside your network, and every line of code that touches it is open to read.

      Read the self-hosting guide Read the source

      • Your data stays in your network

        Messages, pull requests and tickets go into a graph on your own disk. The only outside call is to the AI model you choose, with your own key.

      • Ready for more capable AI

        AI tools can read, never write. Generated queries run as a read-only database user with a time limit, and a person approves every action before it posts.

      • Every claim carries its proof

        Each sentence quotes its source word for word, checked in code before you see it. No quote, no sentence.

      • Read every line

        Apache-2.0. All 166 graph queries live in plain files, each with a test, so a security review is reading, not guessing.

      • Costs you control

        Use your own Anthropic key under a hard daily cap, or your team’s Claude, Codex or Cursor subscription over MCP. Graph lookups cost nothing.

      • No lock-in

        Standard Cypher on FalkorDB. Dump the whole graph to one file and restore it on any machine.

      Why

      Yaan’s answers live in the links between people, work and decisions, so the engine that holds those links decides how fast, and how right, an answer is. Yaan runs on FalkorDB: the Rust-based, in-memory graph database on Redis that stores adjacency as sparse matrices and runs traversals as linear algebra.

      Rust-based

      • 2.6×Yaan’s score with the FalkorDB graph versus without it, held-out (63.6 vs 24.2)Measured by us
      • 3–28 msp50 per graph query, on 38,535 nodes and 96,047 edgesMeasured by us
      • 496×lower p99 latency than Neo4j: 83 ms against 41,157 msFalkorDB’s benchmark
      • 6×less memory than Neo4j: 100 MB against 600 MBFalkorDB’s benchmark

      Three answers only a graph gives

      // states_at.cypher: the decisions in force at one moment
MATCH (:Product {id: $product_id})<-[:IN_PRODUCT]-(i:Issue)<-[:AFFECTS]-(d:Decision)
WHERE d.kind = 'issue_status' AND d.valid_from_ms <= $as_of_ms
  AND (d.valid_to_ms IS NULL OR d.valid_to_ms > $as_of_ms)
RETURN i.id AS subject_id, d.value AS value, d.id AS decision_id
LIMIT $limit// rank_companies.cypher: companies by the issues their customers reported
MATCH (:Product {id: $product_id})<-[:IN_PRODUCT]-(i:Issue)-[:REPORTED_BY]->(c:Customer)
OPTIONAL MATCH (c)-[:WORKS_AT]->(co:Company)
OPTIONAL MATCH (i)-[:REPORTED_IN]->(m:Artifact)
// … group by company, keep each issue's status and report as evidence
RETURN key AS id, name, issues
LIMIT $limit// person_pagerank.cypher: FalkorDB's native PageRank over who works with whom
CALL algo.pageRank('Person', 'COLLAB') YIELD node, score
RETURN node.id AS id, score
ORDER BY score DESC
LIMIT $limit
// also native: algo.betweenness, algo.labelPropagation, shortestPath
